# 回测入门：从第一性原理理解代码（完整版）

> 本文档面向初学者，用「第一性原理」拆解回测的本质，配合大量流程图帮你建立直觉。
> 
> 所谓第一性原理，就是不停留于「怎么做」，而是先问「为什么」和「是什么」。

---

## 一、回测的本质是什么？

### 1.1 一个思想实验

假设你有一个「想法」：

> *"当券商分析师集体上调某只股票的盈利预期时，这只股票接下来会涨。"*

你怎么知道这个想法对不对？

**最笨但最靠谱的办法**：回到过去，假装你在每一个历史时点都知道当时的预期变化，然后按这个想法买卖，看最后赚了还是亏了。

这个「假装回到过去做交易」的过程，就是**回测（Backtest）**。

```
┌─────────────────────────────────────────────────────────────┐
│                     回测的本质                               │
│                                                             │
│   历史数据  +  交易规则  ──►  模拟交易  ──►  盈亏结果        │
│      ▲           ▲                              │           │
│      │           │                              ▼           │
│   已经发生    你制定的                            评估想法    │
│   无法改动    买卖逻辑                            是否可行    │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 回测的第一性拆解

任何回测系统，无论多复杂，都可以拆成五个不可再减的要素：

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│  数据   │───►│  信号   │───►│  交易   │───►│  收益   │───►│  评估   │
│  DATA   │    │ SIGNAL  │    │  TRADE  │    │ RETURN  │    │ EVAL    │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
   是什么？       买什么？       怎么买？       赚多少？       好不好？
```

下面逐层讲解，并对应到本项目的代码。

## 二、第一层：数据（Data）

### 2.1 为什么数据是地基？

回测有一句行话：**"Garbage in, garbage out"**（进去是垃圾，出来也是垃圾）。

如果你的历史数据本身有错（比如把未来的数据混进去了），那回测结果再漂亮也是假的。

### 2.3 数据清洗：三大数据卫生问题

在把原始数据变成可用因子之前，本项目处理了三个关键的数据质量问题（`factors.py` 的注释明确指出了这三个问题）：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    数据清洗三道关（factors.py）                      │
│                                                                     │
│   原始数据                                                          │
│      │                                                              │
│      ▼                                                              │
│   ┌─────────────────────────┐                                       │
│   │ 问题1：close=0           │  次新股上市前或停牌期间               │
│   │ （新股上市前占位数据）    │  Wind 会用 close=0 占位              │
│   │                         │                                       │
│   │ 处理：视为缺失（NaN）     │  df.loc[df["close_hkd"] <= 0] = np.nan│
│   │                         │  收益率不会爆炸（除零错误）            │
│   └─────────────────────────┘                                       │
│      │                                                              │
│      ▼                                                              │
│   ┌─────────────────────────┐                                       │
│   │ 问题2：41% 预期亏损       │  很多公司 fy1_np_avg <= 0             │
│   │ （预测净利润为负）        │  如果用 ΔF/F（百分比变化），会失真     │
│   │                         │                                       │
│   │ 处理：不用 ΔF/F，改用      │  delta / mkt_cap                     │
│   │       市值标准化 ΔF/mkt_cap│  用绝对金额变化除以市值               │
│   │                         │  既公平又稳定                         │
│   └─────────────────────────┘                                       │
│      │                                                              │
│      ▼                                                              │
│   ┌─────────────────────────┐                                       │
│   │ 问题3：极端值             │  某天某只小股票预期修正异常大         │
│   │ （异常值主导组合）        │  如果不处理，极端值会主导排序         │
│   │                         │                                       │
│   │ 处理：Winsorize 1%/99%    │  每周截面截断：                       │
│   │       （截尾处理）        │  • 最大的 1% → 压缩到第 99 分位数    │
│   │                         │  • 最小的 1% → 提升到第 1 分位数     │
│   └─────────────────────────┘                                       │
│      │                                                              │
│      ▼                                                              │
│   清洗后的数据面板                                                  │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.4 跨年修复：为什么元旦要特别处理？

这是本项目一个非常关键且容易忽略的数据处理逻辑：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    跨年修复原理（factors.py）                        │
│                                                                     │
│   正常情况：                                                        │
│   第1周 fy1_np_avg = 预测2024年净利润 = 100亿                       │
│   第2周 fy1_np_avg = 预测2024年净利润 = 105亿                       │
│   diff() = +5亿  ←  真实修正                                       │
│                                                                     │
│   跨年时的陷阱（每年1月第一周）：                                    │
│   12月最后一周 fy1_np_avg = 预测2024年净利润 = 100亿               │
│   1月第一周    fy1_np_avg = 预测2025年净利润 = 110亿  ← 标的不同了！│
│                                                                     │
│   如果不处理：diff() = +10亿  ←  假上调！全市场同时"大幅上调"       │
│                                                                     │
│   本项目的修复：                                                    │
│   year_changed = 日期年份发生变化的首周                             │
│   delta = diff().where(~year_changed)  ←  换年首周置 NaN            │
│                                                                     │
│   效果：                                                            │
│   • 换年首周的预期修正因子 = NaN（不参与选股）                       │
│   • 避免了每年1月的系统性假信号                                     │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.5 从原始数据到「因子面板」

原始数据不能直接用来交易，需要加工成**因子（Factor）**。

什么是因子？简单说就是一个**可以排序的数值**，用来判断股票好不好。

本项目的因子面板构建流程：

```
┌─────────────────────────────────────────────────────────────────────┐
│                 因子面板构建流程（build_factor_panel）               │
│                                                                     │
│   输入：panel_data 原始数据（100股 × 周频）                         │
│      │                                                              │
│      ├───► 计算收益率 ret = close_hkd.pct_change()                 │
│      │                                                              │
│      ├───► 计算 FY1/FY2 预期修正（已修跨年跳变）                    │
│      │    fy1_rev_norm = diff(fy1_np_avg) / mkt_cap                │
│      │    fy2_rev_norm = diff(fy2_np_avg) / mkt_cap                │
│      │                                                              │
│      ├───► 计算 NTM 滚动口径（跨年平滑）                            │
│      │    w = 1 - (day_of_year - 1) / days_in_year                │
│      │    ntm_np = w * fy1_np_avg + (1-w) * fy2_np_avg            │
│      │    ntm_rev_norm = diff(ntm_np) / mkt_cap                    │
│      │                                                              │
│      ├───► 计算预期类增强因子                                       │
│      │    rev_norm_4w      = 过去4周 FY1 修正累计                  │
│      │    rev_diffusion_8w = 过去8周(上调周数-下调周数)/8           │
│      │    eps_rev_norm     = diff(fy1_eps) / close_hkd            │
│      │                                                              │
│      ├───► 计算分歧 & 覆盖因子                                      │
│      │    disagree_drop = -diff(fy1_disagree)  ← 分歧收敛看多      │
│      │    instnum_chg    = diff(fy1_instnum)   ← 覆盖增加看多      │
│      │                                                              │
│      ├───► 计算价量 & 估值因子                                      │
│      │    mom_12w       = 12周价格动量                             │
│      │    reversal_1w   = -ret            ← 上周跌的本周买          │
│      │    low_vol_12w   = -ret.rolling(12).std()  ← 波动小的好    │
│      │    ep             = 1 / pe_ttm     ← 盈利收益率（价值）      │
│      │                                                              │
│      ├───► 计算背离因子                                             │
│      │    exp_price_divergence = zscore(rev_norm_4w) - zscore(mom_4w)│
│      │    ← 预期在涨但股价还没跟上的股票                             │
│      │                                                              │
│      ├───► 合并市场收益，算超额收益                                  │
│      │    exret = ret - mkt_ret（恒生科技指数收益）                  │
│      │                                                              │
│      └───► 截面 Winsorize（所有因子和收益）                         │
│           每周分组，1%/99% 截断                                     │
│                                                                     │
│   输出：fac DataFrame（包含所有原始列 + 所有因子列）                 │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.6 因子库全景

本项目注册了 **12 个因子**，分为四大类：

> ⚠️ **先澄清一个容易混淆的问题**：**因子库 ≠ 同时用的因子**。
> 
> 下面12个因子是「弹药库」，当前策略每次**只选其中一个**作为选股信号。其他因子用来做对比研究、灵敏度测试、或者未来扩展多因子策略。
> 
> 如果你打开看板（dashboard.py），侧边栏有一个下拉框可以切换这12个因子中的任意一个，全站的分析、回测、选股都会跟着切换。这就是「单因子框架」的含义。

```
┌─────────────────────────────────────────────────────────────────────┐
│                         因子库（FACTORS）                            │
│                                                                     │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  预期类（需分析师覆盖）                                       │  │
│  │  • fy1_rev_norm        FY1 预期修正（当年净利润预期上调÷市值）│  │
│  │  • fy2_rev_norm        FY2 预期修正（明年净利润预期上调÷市值）│  │
│  │  • ntm_rev_norm        NTM 滚动口径（跨年平滑，不跳变）       │  │
│  │  • rev_norm_4w         FY1 修正动量（过去4周累计）            │  │
│  │  • rev_diffusion_8w    修正扩散度（方向一致性）               │  │
│  │  • eps_rev_norm        FY1 EPS 修正（每股盈利口径）           │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  分歧 & 覆盖                                                  │  │
│  │  • disagree_drop       分歧收敛（分歧度下降看多）             │  │
│  │  • instnum_chg         覆盖增加（分析师机构数增加看多）       │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  价量 & 估值                                                  │  │
│  │  • mom_12w             12周价格动量（追涨）                   │  │
│  │  • reversal_1w         短期反转（上周跌的买）                 │  │
│  │  • low_vol_12w         低波动（波动小的买）                   │  │
│  │  • ep                  盈利收益率（1/PE，越便宜越好）         │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  背离                                                         │  │
│  │  • exp_price_divergence 预期-价格背离                         │  │
│  │    （预期动量z分 − 价格动量z分，预期升但股价还没跟上）        │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  ★ 标注 needs_coverage=True 的因子：选股时额外要求有分析师覆盖      │
│    （fy1_instnum > 0 或 fy2_instnum > 0）                          │
└─────────────────────────────────────────────────────────────────────┘
```

## 三、第二层：信号（Signal）

### 3.1 信号是什么？

因子是一个连续数值，信号是**基于因子做出的买卖决策**。

本项目的信号规则非常简单（简单往往是优点）：

```
┌─────────────────────────────────────────────────────────────┐
│                      信号生成规则                             │
│                                                             │
│   每周对所有股票按选定的因子排序                               │
│                                                             │
│   做多（买入）─────►  排名前 20% 的股票                        │
│   做空（卖出）─────►  排名后 20% 的股票                        │
│   忽略           ───►  中间 60% 的股票                        │
│                                                             │
│   每只股票等权重（各买同样的金额）                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 股池清洗：四道保险栓

初学者最容易忽略的一步：不是每只股票都能买。本项目设置了**四道关卡**：

```
┌─────────────────────────────────────────────────────────────────┐
│                  股池清洗四道保险栓（strategy.py）               │
│                                                                 │
│   全部股票（config/codes.csv 定义的 100 只标的）                │
│      │                                                          │
│      ▼                                                          │
│   ┌─────────────────────┐                                       │
│   │ 第1关：基础可交易    │                                       │
│   │                     │  • close_hkd > 0（有价格）             │
│   │                     │  • amount > 0（有成交量）              │
│   └─────────────────────┘                                       │
│      │                                                          │
│      ▼                                                          │
│   ┌─────────────────────┐                                       │
│   │ 第2关：流动性过滤    │  滚动 ADTV（12周平均日成交额）        │
│   │  (ADTV 筛选)        │  剔除滚动 ADTV 最低的 10%（liq_pct）   │
│   │                     │  排除「买得进但卖不出」的股票          │
│   └─────────────────────┘                                       │
│      │                                                          │
│      ▼                                                          │
│   ┌─────────────────────┐                                       │
│   │ 第3关：退市保险栓    │  读取 config/universe_status.csv      │
│   │  ( alive 标记 )     │  来自 INF stock_lifecycle 数据        │
│   │                     │  • 有 delist_date 的：退市日之后不可用 │
│   │                     │  • is_active=False 的：已退市不可用    │
│   │                     │                                       │
│   │  「幸存者偏差」陷阱：│  用现在的股票列表回测 = 排除已退市     │
│   │  这是回测最大陷阱之一│  这些公司往往最差，排除 = 作弊         │
│   │                     │  本项目通过 alive 标记动态解决         │
│   └─────────────────────┘                                       │
│      │                                                          │
│      ▼                                                          │
│   ┌─────────────────────┐                                       │
│   │ 第4关：数据完整性    │  • 因子值非空（有信号才能排序）        │
│   │                     │  • 市值非空（标准化需要市值）          │
│   │                     │  • 预期类因子：分析师覆盖数 > 0        │
│   │                     │    （确保预期数据真实存在）            │
│   └─────────────────────┘                                       │
│      │                                                          │
│      ▼                                                          │
│   可交易股票池（Eligible Universe）                              │
│   进入 _dropout 选股逻辑                                         │
└─────────────────────────────────────────────────────────────────┘
```

## 四、第三层：交易（Trade）

### 4.1 回测引擎的核心循环

这是整个回测最核心、最需要仔细理解的流程：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    回测主循环（strategy.py backtest）                    │
│                                                                         │
│   开始                                                                  │
│     │                                                                   │
│     ▼                                                                   │
│   ┌──────────────────────────────────────────────────────────────┐     │
│   │ 初始化：设定参数                                              │     │
│   │ • x_col = "fy1_rev_norm" （用哪个因子）                      │     │
│   │ • hold_weeks = 1  （持有几周）                               │     │
│   │ • top_pct = 0.2   （选前20%做多，后20%做空）                  │     │
│   │ • cost_bps = 30   （交易成本，双边30个基点 = 0.3%）           │     │
│   │ • n_drop = 3      （每次最多换3只股票）                       │     │
│   │ • start = None    （回测起始日，可限定）                      │     │
│   └──────────────────────────────────────────────────────────────┘     │
│     │                                                                   │
│     ▼                                                                   │
│   ┌──────────────────────────────────────────────────────────────┐     │
│   │ 预处理：_prepare(fac) 打可交易标记                             │     │
│   │ • 计算 12 周滚动 ADTV                                         │     │
│   │ • 标记流动性（是否在后10%）                                    │     │
│   │ • 标记可交易（价格>0、成交>0）                                │     │
│   │ • 标记未退市（对比 universe_status.csv）                       │     │
│   └──────────────────────────────────────────────────────────────┘     │
│     │                                                                   │
│     ▼                                                                   │

### 4.2 关键概念：非重叠持仓与信号滞后

这是初学者最容易混淆的地方，也是回测中最容易作弊的地方。

**问题**：本周五收盘后你才知道本周的分析师预期数据，那么你能在本周内根据这个数据交易吗？

**答案：不能。** 你最早只能在**下周**交易。

```
时间线：

   第 t 周                              第 t+1 周
   ├─────────────────────┤              ├─────────────────────┤
   │                     │              │                     │
   │  周一至周五           │              │  周一至周五          │
   │  股价涨跌             │              │  股价涨跌            │
   │                     │              │                     │
   │  周五收盘后 ──► 数据公布              │                     │
   │  知道本周预期修正值   │              │                     │
   │                     │              │                     │
   └─────────────────────┘              └─────────────────────┘
            │                                    ▲
            │                                    │
            └─────────► 用这个信号 ──────────────┘
                        交易发生在下周
                        （信号滞后一周）

   收益归属：
   • 第 t 周信号 ──► 赚取的是第 t+1 周的收益
   • 这就是「ret_lookup」的含义：用本周信号，匹配未来收益
```

本项目的 `hold_weeks` 参数控制持有周期：
- `hold_weeks=1`：每周都重新选股（高频，换手率高）
- `hold_weeks=4`：每4周换一次仓（低频，换手率低）

### 4.3 TopkDropout：为什么每次只换3只？

```
┌─────────────────────────────────────────────────────────────────────┐
│                     TopkDropout 示意（n_drop=3）                    │
│                                                                     │
│   上期持有的多头股票（10只）          本期因子排序后的新候选         │
│   ┌─────────────────────────┐        ┌─────────────────────────┐   │
│   │ A  B  C  D  E  F  G  H  │        │ X  Y  Z  A  B  C  D  E  │   │

│   │                         │        │                         │   │

## 五、第四层：收益（Return）

### 5.1 净值曲线是怎么算出来的？

```
┌─────────────────────────────────────────────────────────────────────┐
│                        净值计算流程                                  │
│                                                                     │
│   第1周                                                             │
│   初始资金 = 1.0                                                     │
│        │                                                            │
│        ▼                                                            │
│   周收益率 r1 = 2%                                                   │
│   第1周末净值 = 1.0 × (1 + 0.02) = 1.02                              │
│        │                                                            │
│        ▼                                                            │
│   第2周                                                             │
│   周收益率 r2 = -1%                                                  │
│   第2周末净值 = 1.02 × (1 - 0.01) = 1.0098                           │
│        │                                                            │
│        ▼                                                            │
│   第3周                                                             │
│   周收益率 r3 = 3%                                                   │
│   第3周末净值 = 1.0098 × (1 + 0.03) = 1.0401                         │
│        │                                                            │
│        ▼                                                            │
│   ... 以此类推，cumprod 累积乘积                                     │
│                                                                     │
│   最终净值 = (1+r1) × (1+r2) × (1+r3) × ... × (1+rN)               │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

本项目画出四条净值曲线：
- **多头（Long）**：只买预期修正最强的股票
- **空头（Short）**：只卖预期修正最弱的股票
- **多空（Long-Short）**：同时做多头和空头（市场中性）
- **基准（Benchmark）**：恒生科技指数（用来对比）

### 5.2 多空组合的含义

```
┌─────────────────────────────────────────────────────────────────────┐
│                      多空组合示意                                    │
│                                                                     │
│   你的资金                                                          │
│      │                                                              │
│      ├───► 一半做多最强股票 ──► 如果它们涨，你赚钱                   │
│      │                                                              │
│      └───► 一半做空最弱股票 ──► 如果它们跌，你赚钱                   │
│                                                                     │
│   特点：                                                             │
│   • 不赌大盘涨跌（市场中性）                                         │
│   • 赌的是「强者更强，弱者更弱」的因子效果                           │
│   • 大盘涨10%，你的收益 ≈ 多头涨10% - 空头涨10%                      │
│   • 大盘跌10%，你的收益 ≈ 多头跌10% - 空头跌10%                      │
│                                                                     │
│   如果因子有效：                                                     │
│   • 强者涨20%，弱者跌5% ──► 多空收益 = 20% - (-5%) = 25%           │
│   • 即使大盘跌了，你仍然可能赚钱！                                   │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.2 因子库是干什么用的？

既然每次只用一个，为什么要建12个因子的弹药库？三个目的：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    因子库的三大用途                                  │
│                                                                     │
│  用途1：对比研究 ──► 哪个因子「本身」预测力最强？                   │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  因子A：IC均值=0.08, Sharpe=1.2                               │  │
│  │  因子B：IC均值=0.03, Sharpe=0.5  ← 因子A 本身质量更好        │  │
│  │                                                              │  │
│  │  做法：逐个因子跑回测，对比 IC/IR/Sharpe，选「最稳的枪」     │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  用途2：灵敏度测试 ──► 好结果是碰巧还是因子真的有效？               │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  如果「预期修正」因子有效，那与它相关的因子也应该有一定效果：  │  │
│  │  • fy1_rev_norm 有效                                          │  │
│  │  • fy2_rev_norm 也应该有一定效果（同逻辑，只是年份不同）      │  │
│  │  • ntm_rev_norm 也应该有效（跨年平滑版）                      │  │
│  │                                                              │  │
│  │  如果只有fy1有效、其他全废 → 可能过拟合或数据问题            │  │
│  │  如果一族因子都有效 → 说明「预期修正」这个逻辑确实站得住脚   │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  用途3：未来扩展 ──► 多因子合成（目前代码未实现，但思路在此）       │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │  单因子的问题：任何因子都有「失效期」                          │  │
│  │  • 动量因子在震荡市失效                                        │  │
│  │  • 价值因子在成长股牛市失效                                    │  │
│  │  • 预期因子在财报真空期失效                                    │  │
│  │                                                              │  │
│  │  多因子的思路：把多个因子的信号「合成」成一个综合分数          │  │
│  │  • 等权合成：score = z(factor1) + z(factor2) + z(factor3)    │  │
│  │  • IC加权：预测力强的因子给更高权重                            │  │
│  │  • 正交化：去掉因子之间的相关性，保留独立信息                  │  │
│  │  • 机器学习：用模型自动学权重（但容易过拟合）                  │  │
│  └──────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.4 多因子合成的思路（供未来扩展）

虽然目前代码是单因子框架，但因子库已经为多因子扩展埋下了接口。常见的合成思路：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    多因子合成方法对比                                │
│                                                                     │
│  方法1：等权 Z-Score 合成                                           │
│  ─────────────────────                                              │
│  score = z(fy1_rev_norm) + z(disagree_drop) + z(mom_12w)          │
│  优点：简单、稳健、不容易过拟合                                     │
│  缺点：没有区分因子好坏，垃圾因子也会混进来                         │
│                                                                     │
│  方法2：IC 加权合成                                                 │
│  ───────────────────                                                │
│  weight_i = max(0, IC_i_mean)  ← 预测力为负的因子权重归零          │
│  score = Σ weight_i × z(factor_i)                                   │
│  优点：好的因子权重高，差的自动被压低                               │
│  缺点：IC 是历史值，未来可能变化                                    │
│                                                                     │
│  方法3：分组正交化（剔除冗余信息）                                  │
│  ─────────────────────────────                                      │
│  先算因子之间的相关性矩阵                                           │
│  对高度相关的因子做正交处理（如 PCA / 残差化）                      │
│  再用正交后的因子合成                                               │
│  优点：去除重复信息，保留独立Alpha                                  │
│  缺点：复杂、可解释性下降                                           │
│                                                                     │
│  方法4：机器学习（XGBoost / 神经网络）                              │
│  ─────────────────────────────────                                  │
│  用历史数据训练模型，自动学习非线性组合                             │
│  优点：理论上效果最好                                               │
│  缺点：极易过拟合，实盘常失效，"黑盒"难以解释                       │
│                                                                     │
│  ★ 本项目当前：方法0 = 单因子，最简单、最不容易过拟合               │
│    未来演进：方法1（等权）→ 方法2（IC加权）→ 方法3（正交化）       │
└─────────────────────────────────────────────────────────────────────┘
```

### 6.2 关键指标解释

| 指标 | 含义 | 好策略的标准 |
|------|------|-------------|
| **CAGR** (年化收益率) | 如果策略每年复利，平均每年赚多少 | 越高越好，但要结合风险看 |
| **波动率** (Volatility) | 收益率的起伏程度 | 越低越好，说明收益稳定 |
| **夏普比率** (Sharpe) | 每承担1单位风险，获得多少超额收益 | > 1 算不错，> 2 很优秀 |
| **最大回撤** (Max Drawdown) | 从高点到低点的最大亏损幅度 | 越小越好，< 20% 较稳健 |
| **胜率** (Win Rate) | 赚钱周数占总周数的比例 | > 50% 说明「对的时候比错的多」 |
| **信息比率** (IR) | 相对于基准，每单位跟踪误差赚多少 | > 0.5 可用，> 1 很好 |
| **换手率** (Turnover) | 每期换仓的比例 | 越低越好，意味着成本低 |
| **IC** (信息系数) | 因子值与未来收益的相关性 | > 0.05 且稳定，说明因子有预测力 |
| **ICIR** (IC信息比率) | IC的均值 / IC的标准差 | > 0.5 说明预测力稳定 |
| **IC正率** (IC Pos Rate) | IC > 0 的比例 | > 50% 说明方向对的时候更多 |

### 6.3 分层 IC 分析：判断因子是否「真有用」

本项目不仅看回测收益，还做 **三层 IC 分析**（1周、2周、4周前瞻）：

```
┌─────────────────────────────────────────────────────────────────────┐
│                    分层 IC 分析原理                                  │
│                                                                     │
│   每一周：                                                           │
│   ┌───────────────────────────────────────────────────────────────┐ │
│   │  股票  │  本周因子值  │  未来1周收益 │ 未来2周收益 │ 未来4周 │ │
│   │  A     │    +2.5     │     +5%      │    +8%      │   +12%  │ │
│   │  B     │    +1.8     │     +3%      │    +5%      │   +7%   │ │
│   │  C     │    -0.5     │     -2%      │    -3%      │   -5%   │ │
│   │  D     │    -2.0     │     -4%      │    -6%      │   -9%   │ │
│   └───────────────────────────────────────────────────────────────┘ │
│                              │                                      │
│                              ▼                                      │
│                    计算 Spearman 秩相关系数                          │
│                    （因子排名 vs 收益排名 的相关性）                  │
│                              │                                      │
│                              ▼                                      │
│   ┌───────────────────────────────────────────────────────────────┐ │
│   │ h=1 周 IC = +0.15  ←  短期预测力                               │ │
│   │ h=2 周 IC = +0.12  ←  中期预测力                               │ │
│   │ h=4 周 IC = +0.08  ←  长期预测力衰减（正常）                   │ │
│   └───────────────────────────────────────────────────────────────┘ │
│                              │                                      │
│                              ▼                                      │
│   对所有周重复，得到 IC 时间序列：                                    │
│   • IC均值 = 平均预测力                                             │
│   • ICIR   = 预测力稳定性（均值/标准差）                            │
│   • IC正率 = 方向正确的比例                                         │
│                                                                     │
│   好处：独立于具体的 top_pct 参数，直接衡量因子本身的「质量」       │
└─────────────────────────────────────────────────────────────────────┘
```

## 八、第六层：研究层（Research）

在跑回测之前，本项目还做了一套**统计分析**来验证「预期修正是否真的能预测股价」。这就是 `analysis_v2.py` 的作用。

### 7.1 为什么需要研究层？

```
┌─────────────────────────────────────────────────────────────────────┐
│                    回测 vs 统计分析的区别                            │
│                                                                     │
│   回测（Backtest）              统计分析（Research）                │
│   ├─ 模拟完整的交易流程          ├─ 验证因果关系                     │
│   ├─ 包含成本、换手等细节        ├─ 回答「X 是否导致 Y」            │
│   ├─ 结果是「赚了多少钱」        ├─ 结果是「显著性 p 值」            │
│   └─ 可能过拟合（参数调太多）    └─ 更不容易被「美化」              │
│                                                                     │
│   两者关系：统计分析通过 → 才有信心做回测                            │
│            回测效果好  → 才能落地交易                                │
└─────────────────────────────────────────────────────────────────────┘
```

### 7.2 四种统计方法

```
┌─────────────────────────────────────────────────────────────────────┐
│                    研究层方法论（analysis_v2.py）                    │
│                                                                     │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 1. 交叉相关（Cross Correlation）                              │  │
│  │                                                             │  │
│  │    问题：预期修正和股价，谁领先谁？                           │  │
│  │                                                             │  │
│  │    lag = +1 周：X_t  vs  Y_{t+1}  → 预期领先股价（好）      │  │
│  │    lag = -1 周：X_t  vs  Y_{t-1}  → 股价领先预期（坏）      │  │
│  │                                                             │  │
│  │    做法：逐股算 Pearson 相关，再截面平均 + t 检验             │  │
│  │    输出：每个 lag 的 mean_r、n_stocks、t_stat、p_value        │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 2. 双向回归（Newey-West HAC）                                 │  │
│  │                                                             │  │
│  │    方向 A：预期修正_t → 未来超额收益_{t+k}                    │  │
│  │    方向 B：超额收益_t → 未来预期修正_{t+k}                    │  │
│  │                                                             │  │
│  │    ★ 关键：用 Newey-West 标准误修正周频自相关                 │  │
│  │       周数据有自相关，普通 OLS 会虚高 t 值                    │  │
│  │       HAC 标准误让结果更可信                                  │  │
│  │                                                             │  │
│  │    输出：beta（斜率）、t、t 检验 p 值、R²                     │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 3. 事件研究（Event Study）                                    │  │
│  │                                                             │  │
│  │    问题：当预期大幅上调/下调时，前后股价怎么走？                │  │
│  │                                                             │  │
│  │    事件定义：每周取 x 的 top 10%（大幅上调）/ bottom 10%      │  │
│  │    观察窗口：事件前后 ±8 周的累计超额收益（CAR）              │  │
│  │                                                             │  │
│  │    输出：上调/下调事件在各周的平均 CAR + t 检验               │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                     │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 4. Granger 因果检验（VAR 模型）                               │  │
│  │                                                             │  │
│  │    问题：预期修正「格兰杰导致」股价变化，还是反过来？           │  │
│  │                                                             │  │
│  │    做法：截面平均时间序列 → VAR 向量自回归模型                │  │
│  │          检验 x 的滞后项是否对 y 有显著预测力                 │  │
│  │                                                             │  │
│  │    输出：F 统计量 + p 值                                      │  │
│  └──────────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────────┘
```

## 十二、一句话总结

> **回测 = 用历史数据诚实地模拟「如果一个想法在过去被执行，结果会怎样」。**
> 
> 诚实 = 不偷看未来 + 不忽略成本 + 不挑选幸存者 + 不美化数据 + 不只看好的一面。
