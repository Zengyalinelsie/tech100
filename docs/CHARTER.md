## 一、原始动机 — 为什么做这个项目？

> **一句话**：想搞清楚港股科技股里，**"分析师的盈利预期"和"市场股价"，到底谁先动、谁跟谁。**

### 背后的核心信念

- **港股科技 100** = 中国新经济的核心标的（腾讯、美团、阿里、宁德、比亚迪、AI 链……），是中长期资金配置中国创新的主战场之一
- **一致预期（Wind west_netprofit）** = 卖方分析师对未来盈利的集体看法 — 这是机构投资者**"想法的地图"**
- **股价**则是市场所有参与者**"行为的结果"**
- 两者之间的领先-滞后关系，是回答"市场有效性"和"信息扩散速度"的关键

### 这件事有什么投资价值？

| 假设 | 如果成立 | 如何赚钱 |
|------|---------|---------|
| **预期领先股价**（k>0） | 预期上调 → 股价后涨 | 监控预期调整，提前布局 |
| **股价领先预期**（k<0） | 股价先涨 → 预期跟随调高 | 跟随股价动量，不看预期 |
| **基本同步**（k=0） | 市场快速反应 | 不存在套利窗口，做指数即可 |

港股相对 A 股**机构化程度高、分析师质量高**，理论上预期是更好的领先指标 — 但**这是经验问题，需要数据说话**。这是项目存在的全部理由。

## 二、最终目标 — 做到什么程度算成功？

按野心从低到高分三档：

### 🥉 最低目标（描述性看板）
- 一站式看 100 只科技股的"预期 vs 股价同步状况"
- 知道某只股票当前是"预期领先"、"股价领先"还是"基本同步"
- 数据每日自动更新，看板每日刷新

**状态：已基本达成 ✅**

### 🥈 中级目标（统计性研究）
- 建立可信的"领先-滞后关系"统计模型
- 识别**什么条件下关系稳定**（牛/熊/行业/覆盖度）
- 量化"盈利惊喜"（实际 vs 预期）对股价的影响
- 区分**统计显著**的关系 vs 噪声

**状态：方法框架已搭，但数据不足 + 显著性未标注 ⚠**

### 🥇 高级目标（可交易因子）
- 把"最优 lag"、"双向回归 R²"、"Granger p-value"、"预期分歧度"等指标**因子化**
- 在历史数据上做**简单回测**（多头：预期领先 + 显著 + 分歧低；空头：股价领先 + 分歧高）
- 输出可执行的**信号文件 / 报告**，给真实策略用

**状态：尚未启动 ❌**

## 三、当前已有什么（资产盘点）

### 1. 数据资产

| 项 | 现状 |
|---|---|
| 标的 | 100 只港股科技股（`config/codes.csv`，从 0013.HK 到 9999.HK） |
| 数据源 | Wind 个人版终端，用 Excel `s_west_*` / `s_dq_close` / `s_info_*` 公式拉 |
| 入库的时间序列 | **每周** 1 行 × 2 个字段：`netprofit_avg`（FY2026 预期均值）、`close_hkd` |
| 入库的静态指标 | 6 个字段 × 2 个年度：机构数、均值、最大、最小、中值、标准差 |
| 实际入库跨度 | **约 87 周 ≈ 1.7 年**（2024-09 → 2026-05） |
| 数据库 | SQLite `data/wind_history.db`，2 张表：`weekly_data`、`static_indicators` |

### 2. 分析框架（`app/leadlag_analysis.py`）

| 层 | 方法 | 产出 |
|---|------|------|
| Layer 1 | 交叉相关性（截面平均 Pearson）+ 单股最优 lag | 全市场 lag profile + 个股 lag 分布 |
| Layer 2A | 双向预测回归（OLS） | A 方向（预期→股价）vs B 方向（股价→预期）R² 对比 |
| Layer 2B | 事件研究（90/10 分位 ΔF + CAR 曲线） | 事件前后 8 周 CAR + 显著性 |
| Layer 3A | 状态依赖（按牛/熊/覆盖度切样本） | 4 个分组的交叉相关图 |
| Layer 3B | VAR + Granger 因果检验 | 全市场"预期↔股价"双向因果 p-value |
| Layer 3C | IRF 脉冲响应函数 + 95% CI | 冲击的动态反应路径 |

### 3. 看板（`app/dashboard.py`，已部署 Streamlit Cloud）

- 三 Tab 结构：📊 市场整体 / 🔍 个股深度 / 🏆 100 家排行榜
- 顶部 5 卡 KPI 状态栏
- 本周事件被动表（最近 4 周触发显著调整的股票）
- 个股深度：K 线 + 该股 lag/回归/CAR
- 排行榜：Top4 极值卡 + 可排序大表 + sparkline + CSV 导出
- 莫兰迪色卡（红涨蓝跌柔和版）

### 4. 自动化

- `scripts/update_wind_data.py`：xlwings 驱动 Excel，逐只股票把 wind_code 写 B1，等 Wind 计算后读结果存 SQLite
- `crontab` 每个工作日 17:30 自动跑
- Push 到 GitHub → Streamlit Cloud 自动 rebuild

### 5. template.xlsx 现状（最新发现）

**已经被扩展过**，远超我之前的认知：
- 时间序列 `A11:G395` = **385 行 ≈ 7.4 年周频**（不是 89 行）
- 列结构：A 日期 | B FY2026 均值 | C 股价 | D 机构数 | E 标准差 | F 中值 | G FY2025 均值
- **6 个时间序列字段**已经在 Excel 公式里，但**只有 B/C 两列被 update_wind_data.py 读取入库**

## 四、目标 vs 现状的差距（Gap 分析）

### Gap 1 🔴 数据深度严重不够（最大瓶颈）
| 现状 | 需要 |
|------|------|
| 87 周入库 | 至少 260 周（5 年）入库 |
| 67% 周 ΔF = 0（噪声占主导） | 拉长数据 + 加分歧度过滤事件 |
| 只覆盖 1 次不完整牛熊周期 | 2-3 个完整周期才能验证状态依赖 |

**根因**：每日采集只回看 89 周，且每天用 update_date 覆盖。template 已经能拉 7.4 年但**没人去读 100 行之外**。

### Gap 2 🟡 字段太单一
| 现状 | 需要 |
|------|------|
| 时间序列只有 `netprofit_avg + close` | 加 `inst_num`、`netprofit_std`（分歧度）、`netprofit_median` |
| 没有 FY2025（去年）做参照 | 加 G 列 FY2025 让"近年盈利变化"可比 |
| 没有财报实际公告日 | 事件研究改为 PEAD（公告后盈利漂移） |
| 没有行业分类 | 100 股需要 5-8 个行业切片 |
| 没有市场基准（恒指/恒科） | 计算超额收益用等权 100 股有 bias |

### Gap 3 🟡 方法学有可改进点
- **事件阈值 90/10 太宽** → 实际是"任何变化"而非"大幅变化"
- **OLS 回归没用 Newey-West** → 周频序列自相关明显，t-stat 虚高
- **VAR/Granger 用全市场截面平均** → 失去可交易性
- **状态依赖样本太小**（每组 ~40 周）→ 显著性不可信

### Gap 4 🟢 UI 已基本成型，但有几个小改进
- **没有显著性标记**（用户可能基于 r=0.05 这种噪声做决策）
- **没有行业筛选**
- **没有滚动窗口 lag 稳定性图**（lag 是稳定的还是抖动？）

4. **不污染 main 分支**。所有大改在 quant-v5（或后续版本分支）上做，验证完再合回 main。
